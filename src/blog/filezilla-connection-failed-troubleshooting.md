## 先看日志，再动手

上周帮同事处理一个上传任务，他连试了半个多小时，把 FileZilla 卸载重装了两遍，问题依旧。我接手后只做了一件事：让他把消息日志区往上翻，第一行写着 `Status: Connection attempt failed with "ECONNREFUSED"`。端口被防火墙挡了，和服务端软件本身毫无关系。

所以这篇实操帖的第一原则是：**别猜，先读日志**。FileZilla 的日志信息其实很直白，只要按错误码对号入座，排查顺序可以非常短。文中版本信息以 2025 年 3 月发布的 3.68.1 为准，旧版本界面略有差异，但日志关键字基本一致。

## 错误码速查与解决顺序

我习惯按"由外到内"的顺序排查：先确认网络通不通，再看协议与端口，然后看被动模式与证书，最后才怀疑账号权限。顺序反了，就容易在账号密码上反复折腾，其实根本连握手都没走到。

### 第一步：确认基础网络与端口

1. 打开站点管理器，检查主机地址是否写成了 `ftp://` 前缀或带路径，FileZilla 只需要纯域名或 IP。
2. 在命令行执行 `telnet 主机 21`（SFTP 用 22），若立即报连接被拒，说明端口没开放，先找服务端或防火墙确认。
3. 若提示超时而非拒绝，多半是中间网络丢包或被安全设备拦截，可换手机热点测试对比。

`ECONNREFUSED` 通常对应端口未监听；`ETIMEDOUT` 则更像链路或策略问题。这两者的处理方向完全不同。如果你还没装好客户端，先参考[官方下载与安装指引](/blog/filezilla-download-official-guide/)，避免从第三方站点拿到被改包的版本。

### 第二步：核对协议类型

很多人把 SFTP 当成"加密的 FTP"，其实两者是完全不同的协议。站点管理器里协议选错，日志会直接报 `Connection attempt failed with "ECONNREFUSED"` 或协议不匹配。FTP 走 21，FTPS 走 990 或 21 加显式 TLS，SFTP 走 22。

如果你要连的是云服务器，大概率该用 SFTP，具体配置可以看[SFTP 配置步骤](/blog/filezilla-sftp-setup-guide/)。而纯 FTP 的首次连接流程，[连接教程](/blog/filezilla-ftp-connection-tutorial/)里讲得更细。

### 第三步：处理被动模式与证书

这是我遇到最多的一类。日志出现 `425 Can't open data connection` 或传输卡在 `LIST` 阶段，基本都是被动模式端口没放行。

1. 进入站点管理器 → 传输设置，把传输模式改为"被动"。
2. 在服务端放行一段被动端口范围（如 50000-50100），并在 FileZilla Server 里同步配置。
3. 若用了 NAT，勾选"使用服务器外部 IP"并填写公网地址。

另一类报错是 `Certificate verification failed`，尤其在连自建 FTPS 时。这时不要急着点"总是信任"，先确认证书指纹来源，再按[证书信任处理流程](/blog/filezilla-certificate-approval/)操作。顺便说一句，FileZilla 是 GPL 开源免费软件，官网是 filezilla-project.org，不存在官方收费版，任何让你付费解锁"高级连接功能"的页面都不可信。

### 第四步：最后才查账号与权限

走到这一步，日志一般会明确写 `530 Login incorrect` 或 `550 Permission denied`。前者是账号密码或密钥问题，注意部分服务器要求用户名带域名后缀；后者是目录权限，SSH 登录后用 `ls -ld` 看目标目录属主即可。

## 我的两次踩坑记录

第一次是给客户部署静态站点，FTP 账号密码复制了三遍都对，最后发现是密码里有 `#`，被我在命令行里当注释截断了。第二次更隐蔽：连接能建立，但每次列表都超时，查了半天才发现公司出口做了 FTP 协议识别，把被动模式的数据连接拦了。这两次都说明一件事——日志第一行往往已经告诉你答案，只是我们习惯性往下翻。

排查过程中如果连接反复中断，可以先看[自动重连设置](/blog/filezilla-auto-reconnect-settings/)，把重试次数调大，避免手动反复点击干扰判断；遇到长时间挂起，参考[连接超时排查](/blog/filezilla-connection-timeout-troubleshoot/)的思路逐项排除。

## 常见问题

**Q1：提示 `ECONNREFUSED` 但 telnet 能通，怎么回事？**

多半是协议选错。telnet 通 22 端口说明 SSH 在跑，但站点管理器里协议若仍是 FTP，客户端会去连 21 而被拒。改成 SFTP 再试。

**Q2：能登录但看不到文件列表，一直卡住？**

典型被动模式问题。先改被动模式，再确认服务端被动端口范围已在防火墙放行。若是云主机，安全组也要同步开。

**Q3：提示证书不受信任，可以忽略吗？**

内网自签证书可以，但要先核对指纹。公网服务器出现证书异常，建议先查清来源再决定，不要无脑点信任。

**Q4：同一账号在别的电脑能用，这台不行？**

优先查本机防火墙和代理软件。部分安全软件会拦截 FTP 数据连接，表现为登录成功但传输失败。
