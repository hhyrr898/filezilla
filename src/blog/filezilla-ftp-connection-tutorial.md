有次我用快速连接误将测试文件传到了生产环境，才意识到这种图省事的方法有多危险。每次连接都要在顶部栏重复输入主机、用户名，端口和加密方式也只能靠记忆，不仅效率低下，更极易因疏忽酿成操作失误。

因此，本教程将引导你使用 FileZilla 的站点管理器。通过预设好所有连接参数，它能为你保存不同服务器的配置，实现一键安全连接。这才是规范的工作流，能从根本上杜绝手动输入带来的风险。

所以这篇按我的实际操作顺序写：先把站点存好，再谈加密，最后传第一份文件。软件版本以 **FileZilla 3.67.1** 为准（这是官方当前稳定版，GPL 开源免费，官网是 filezilla-project.org）。界面在 Windows 和 macOS 上基本一致，个别按钮位置略有差别，不影响操作。

## 第一步：新建一个站点

打开 FileZilla，左侧栏没有站点列表时，点菜单「文件 → 站点管理器」，或者直接按快捷键 Ctrl+S（macOS 是 Command+S）。

在弹出的站点管理器窗口左下角，点「新站点」，给它起个能认出来的名字，比如「公司测试 FTP」。名字是给你自己看的，随便起，但别用「1」「aaa」这种，过两个月你自己都想不起来是什么。

右侧的「常规」标签页里，把下面几项填上：

- **协议**：一般 FTP 服务器选「FTP - 文件传输协议」；如果对方只开了 SSH，选 SFTP（关于两者的差别，可以参考我们之前写的 /blog/filezilla-sftp-setup-guide/）。
- **主机**：填服务器地址，域名或 IP 都行，不要带 `ftp://` 前缀，也不要带路径。
- **端口**：FTP 默认 21，SFTP 默认 22。服务商改过端口的话，一定按他给的填。
- **加密**：先不急着定，下一步单独说。
- **登录类型**：选「正常」，然后填用户名和密码。

填完点「连接」，FileZilla 会把这个站点留在列表里，下次直接双击就能进。

## 第二步：加密方式怎么选

这一项坑最多，我见过不少人连接失败，就是因为加密选项和服务端对不上。3.67.1 的「加密」下拉框里有三种可选：

1. **使用显式的 FTP over TLS（推荐）**：这是目前正规 FTP 服务商的主流做法，先明文握手再升级为 TLS 加密，端口还是 21。
2. **要求显式的 FTP over TLS**：和上面一样，但服务端不支持 TLS 时直接拒绝连接，不会退回明文。安全性更高，调试阶段可以先不用它。
3. **使用明文 FTP（不安全）**：账号密码在网络上裸奔，只建议在本地虚拟机或内网测试环境用。

如果服务端是纯 SFTP，那协议要选 SFTP，加密这一栏根本不会出现，因为整条连接走的就是 SSH。

我个人的习惯是：生产环境一律用「要求显式的 FTP over TLS」，测试环境用「使用显式的 FTP over TLS」，留一点兼容余地。第一次连不上时，把这一项换成「使用明文」快速验证一下，能连上就说明是加密协商的问题，而不是账号或网络的问题。

## 第三步：传输设置与字符集

站点管理器里的「传输设置」标签，新手可以先不动。默认「被动」模式对 NAT 和家用路由器更友好，除非服务商明确要求主动模式。

「字符集」标签建议选「自动检测」。中文文件名乱码大多出在这一步：如果自动检测后文件名还是乱，手动切成 UTF-8 再试一次，多数服务器都吃这一套。

如果你需要断线自动重连、或者限制同时传输的文件数，可以在「编辑 → 设置 → 传输」里调。想深入看的可以翻 /blog/filezilla-auto-reconnect-settings/，这里不展开。

## 第四步：首次传输

连接成功后，界面分四块：左边本地目录、右边远程目录、上面日志、下面传输队列。

1. 左边把本地目录切到你放文件的文件夹，右边切到服务器上要放文件的目标目录。
2. 在左边选中文件，右键选「上传」，或者直接拖到右边窗口。
3. 看下面「传输队列」标签，状态从「排队」变成「传输中」，再到「成功」。
4. 传完去右边刷新一下（按 F5），确认文件真的在，大小一致。

我第一次传的时候犯了个低级错误：本地选中了文件，但远程目录还停在根目录，结果文件传到了 `/` 下，花了半天才找到。所以动手前多看一眼右侧的路径栏，值这几秒钟。

## 常见问题

**问：连接时提示「连接超时」，日志里卡在「正在连接」怎么办？**
先确认端口填对、服务器地址没写错。再看是不是本地防火墙或公司网络拦了 21 端口。命令行 `telnet 主机 21`（或 `nc -vz 主机 21`）能测端口通不通。如果端口通但还是连不上，多半是加密协商或被动模式端口被挡，可以对照 /blog/filezilla-connection-failed-troubleshooting/ 逐条排查。

**问：能登录，但列目录时报 425 或一直卡住？**
大概率是被动模式的端口范围没放开。FileZilla 本身没问题，需要服务端或防火墙放行一段被动端口。临时可以把传输设置切成「主动」试试，能列目录就说明是这个原因。

**问：和 WinSCP 比，我该用哪个？**
两者都能干 FTP/SFTP 的活。FileZilla 跨平台、界面直观，做纯 FTP 传输很顺手；WinSCP 在 Windows 上的脚本和同步功能更细。具体差异我写在 /blog/filezilla-vs-winscp-comparison/，按你的系统和使用场景选就行。

**问：下载安装包去哪拿？**
只从官网 filezilla-project.org 下，别在搜索引擎里点广告位的「高速下载」。版本号和安装细节可以看 /blog/filezilla-download-official-guide/，装完核对一下版本号是不是 3.67.1 这一档。

站点配置、加密方式、首次传输这三件事走通一遍，后面再连别的服务器就是复制粘贴加改几栏的事。真正容易出错的从来不是软件本身，而是加密选项和端口这两处细节。
